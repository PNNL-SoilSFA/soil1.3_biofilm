# File-category provenance

This guide classifies file names by their role and suffix/pattern, rather
than by their extension. It records what is observed in the public-download
inventories and what the historical and runner workflows create. “Supplied”
means present in the downloaded package; it does not claim that this
repository created the file before download.

The authoritative inventory evidence is in
[`activity_replicate_comparison/`](activity_replicate_comparison/). The
observed download contains different layouts for short-term rep1 and
long-term rep7, so a category being present in one inventory does not imply
that it is present in every replicate.

## Categories in the downloaded data

| Filename pattern or category | Role in the public download | Used by runner? | Known origin |
| --- | --- | --- | --- |
| `<base>_w2SD_DAPI_s<1..8>`, `<base>_w3SD_GFP_s<1..8>`, `<base>_w4SD_RFP_s<1..8>` | Eight source fluorescence z-stacks per channel. These are the raw-image inputs used to rebuild each combined image. | Yes. Required by `process_raw_experiment`. | Supplied by the public download; acquired source images, not generated by a script in this repository. |
| `<base>_w1SD_BF_s<1..8>` | Bright-field source image series. | No. The runner uses the supplied stitched bright-field mask instead. | Supplied by the public download; original upstream acquisition. |
| `<base>_w1SD BF_stitched_mask` or `<base>_w1SD BF_stitched_MASK` | Stitched bright-field habitat mask. The case variation is present across layouts; the runner accepts either. | Yes. Required to define zero-valued habitat pixels. | Supplied by the public download. Its pre-download producer is not recorded in this repository. |
| `<base>_w[1-4]SD_*_stitched` without `_mask` | Stitched channel/bright-field image already included in the download. | No. The runner reconstructs the fluorescence stitch from the site z-stacks. | Supplied by the public download; upstream provenance is not recorded here. |
| `<base>_w[2-4]SD_*_s<site>_wo_bg` | Per-site, background-removed fluorescence product. Observed in the rep1 inventory. | No. | Supplied in that download. It is not written by `RawImageProcessing.py` or the runner; its upstream producer is unknown to this repository. |
| `<base>_w[2-4]SD_*_s<site>_masked` | Per-site masked fluorescence product. Observed in the rep1 inventory. | No. | Supplied in that download. Do not confuse it with the runner’s per-*channel combined-stitch* `_masked` output below. Its upstream producer is unknown here. |
| `random_windows/`, thumbnails, composites, `.nd` metadata | Ancillary acquisition/window products, particularly in rep7. | No. | Supplied by the public download; not created by the runner or post-analysis scripts. |

`<base>` is `<sample_id>_<substrate>_1`; `<site>` is `1` through `8`.
For the input layouts and literal examples, see
[`raw_image_processing_file_types.md`](raw_image_processing_file_types.md).

## Products generated by raw processing

The historical `RawImageProcessing.py` and the shared runner processing both
operate on the source mask and 24 fluorescence stacks. Their output root is
different: the historical notebook uses hard-coded folders, whereas the
runners use `--output-dir` (or their documented `results/` defaults).

| Filename pattern | Created by historical `RawImageProcessing.py` | Created by runner `process_raw_experiment` | Meaning |
| --- | --- | --- | --- |
| `<base>_<channel>_masked.TIF` | Yes | Yes | Stitched maximum-z projection after rolling-ball background removal and habitat-mask application. This is one image per channel, not the supplied per-site `s<site>_masked` category. |
| `<base>_<channel>_processed.TIF` | Yes | Yes | Thresholded and normalized per-channel image. |
| `<base>_<channel>_processed.csv` | Yes | Yes | Numeric CSV representation of the processed channel. |
| `<base>_<channel>_sharp.TIF` | Yes | Yes | Sharpened/binary-like per-channel processed product. |
| `<base>_combined_processed.TIF` | Yes | Yes | Three-plane combined processed image in RFP/GFP/DAPI order. |
| `<base>_combined_processed_sharp.TIF` | Yes | Yes | Three-plane combined sharpened image. |
| `<base>_combined_processed.pkl` | Yes | Yes | Pickled unsharpened combined array. The 1.3.1 spatial analysis consumes this runner product. |
| `<base>_combined_processed_small.TIF`, `<base>_combined_processed_small_sharp.TIF`, `<base>_combined_processed_1d.png`, `<base>_combined_processed_1d_sharp.png` | Yes | No | Historical notebook display products only. |
| `<base>_preview.png` | No | Yes | Runner-only review image containing a combined image and population-density profile. |

## Products generated by 1.3.1 analysis

Only Experiment 1.3.1 runs the post-analysis branches. These outputs are
created by `run_experiment_1_3_1.py` after raw processing; they are not
download inputs and are not generated by `RawImageProcessing.py` alone.
Every table is written as both `.pkl` and `.tsv`.

| Output branch and patterns | Source calculation | Meaning |
| --- | --- | --- |
| `PostAnalysis_spatial_sampling/pop_densities_wo_outliers`, `pop_volumes_wo_outliers` | `temporal_tables` using records selected by `experiment_1.3.1_metadata.csv` | Temporal density and volume tables for the outlier-excluded branch. |
| `PostAnalysis_spatial_sampling/spatial/pop_vol_1d_df_480_wo_outliers`, `pop_den_1d_df_480_wo_outliers` | `random_spatial_table` | Random 480-pixel spatial windows (100 trials by default); an integer `--seed` makes their selection reproducible. |
| `PostAnalysis_spatial_sampling/plots/temporal_biomass.png`, `spatial_biomass.png` | Runner plotting helpers | Static review plots of the outlier-excluded tables. |
| `PostAnalysis_with_outlier/pop_densities`, `pop_volumes` | `temporal_tables` using every processed record | Temporal density and volume tables for the full, outlier-inclusive branch. |
| `PostAnalysis_with_outlier/spatial/pop_vol_1d_df_500`, `pop_den_1d_df_500`, `delta_pop_vol_1d_df_500`, `delta_pop_den_1d_df_500` | `full_spatial_tables` | Complete 500-pixel spatial windows and differences at steps 1, 10, and 100. |
| `PostAnalysis_with_outlier/plots/temporal_biomass.png`, `spatial_biomass.png` | Runner plotting helpers | Static review plots of the full branch. |

Experiment 1.3.2 creates only raw-processing products. It intentionally has
no `PostAnalysis_*` output tree.

## Practical provenance rule

Treat every category listed in “downloaded data” as read-only input, even if
its name looks processed (`_wo_bg`, `_masked`, or `_stitched`). Treat every
category listed in the latter two sections as a reproducible result. Point a
runner at a downloaded-data directory only through `--data-dir`; choose a
separate `--output-dir` for retained results. The tests follow the same rule
and remove their temporary inputs and outputs on completion.
