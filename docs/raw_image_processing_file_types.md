# `RawImageProcessing.py` filename conventions

This note documents the literal filename conventions in the historical
[`RawImageProcessing.py`](../RawImageProcessing.py) notebook export. It is a
description of that script, not a specification for the reviewer runners.
The current runners deliberately retain the principal processed-image names,
but do not create every historical display product.

## Naming parts

`<base>` means the acquisition identifier followed by `_1`. In replicate 1,
the acquisition identifier is assembled as `<timepoint>_<carbon>` (for
example, `11.22.21_17_Chitin`). In replicates 2 and 3 it is the acquisition
directory name itself (for example, `02.09.22_11AM_Chitin`). `_1` is an
image-series index, not part of the acquisition identifier. The historical
processing loops are explicitly limited to series 1.

`<channel>` is exactly one of `w4SD RFP`, `w3SD GFP`, or `w2SD DAPI`. These
are processed in that order and become the red, green, and blue planes,
respectively, in combined images. `<site>` is an integer from 1 through 8.
The embedded spaces are literal parts of the filenames.

## Files read

For each acquisition, the script reads one mask plus 24 fluorescence TIFF
files: eight sites for each of the three channels. It does not discover files
by extension or glob; it constructs every expected path directly, so all
parts of each name must match.

| Filename type / example | Applies to | Generated by | What it is / how it is used |
| --- | --- | --- | --- |
| `<base>_w1SD BF_stitched_MASK.tif` — `11.22.21_17_Chitin_1_w1SD BF_stitched_MASK.tif` | Replicate 1 only | Not generated by a script in this repository; supplied in the source-data package | Bright-field stitched mask. `get_mask` converts its zero-valued pixels into the analysis mask, which limits each fluorescence projection. The spelling uses uppercase `MASK`. |
| `<base>_w1SD BF_stitched_mask.tif` — `02.09.22_11AM_Chitin_1_w1SD BF_stitched_mask.tif` | Replicates 2 and 3 only | Not generated by a script in this repository; supplied in the source-data package | Same role as the preceding file, but with lowercase `mask`. This capitalization difference is hard-coded in the historical script. |
| `<base>_<channel>_s<site>.TIF` — `11.22.21_17_Chitin_1_w3SD GFP_s6.TIF` | All three replicates | Not generated by a script in this repository; supplied in the source-data package | One fluorescence, multi-page TIFF z-stack for a field/site. The script reads sites `s1`–`s8`, stitches them into a two-row image at every z position, and takes a maximum-z projection. |

## Files produced

The output directory is hard-coded per replicate in the historical script as
`results/results_rep1`, `results/results_rep2`, or `results/results_rep3`
under its `work_dir`. The table reflects the filenames the script writes.

| Filename type / example | Generated by | What it is / downstream use |
| --- | --- | --- |
| `<base>_<channel>_masked.TIF` — `11.22.21_17_Chitin_1_w4SD RFP_masked.TIF` | `RawImageProcessing.py` | Per-channel maximum-z projection after rolling-ball background removal and application of the bright-field mask. It is an intermediate image before thresholding and normalization. |
| `<base>_<channel>_processed.TIF` — `11.22.21_17_Chitin_1_w4SD RFP_processed.TIF` | `RawImageProcessing.py` | Per-channel masked image after thresholding and normalization to `uint16` in the 0–65535 range. |
| `<base>_<channel>_processed.csv` — `11.22.21_17_Chitin_1_w4SD RFP_processed.csv` | `RawImageProcessing.py` | Comma-separated numeric array of the corresponding processed channel image, written with `numpy.savetxt`. |
| `<base>_<channel>_sharp.TIF` — `11.22.21_17_Chitin_1_w4SD RFP_sharp.TIF` | `RawImageProcessing.py` | Binary-like sharpened version of the normalized channel image, made with the script's `sharping` threshold. |
| `<base>_combined_processed.TIF` — `11.22.21_17_Chitin_1_combined_processed.TIF` | `RawImageProcessing.py` | Three-plane combined image with the processed RFP, GFP, and DAPI arrays as red, green, and blue planes. |
| `<base>_combined_processed_sharp.TIF` — `11.22.21_17_Chitin_1_combined_processed_sharp.TIF` | `RawImageProcessing.py` | Three-plane combined image built from the sharpened channel arrays. |
| `<base>_combined_processed.pkl` — `11.22.21_17_Chitin_1_combined_processed.pkl` | `RawImageProcessing.py` | Python pickle containing the unsharpened, combined three-plane NumPy array. Both `PostAnalysis_spatial_sampling.py` and `PostAnalysis_with_outlier.py` load this naming type. |
| `<base>_combined_processed_small.TIF` | `RawImageProcessing.py` | Matplotlib-rendered view of the unsharpened combined image, saved using a `.TIF` filename. Despite `small` in the name, the script does not explicitly rescale the data before plotting. |
| `<base>_combined_processed_small_sharp.TIF` | `RawImageProcessing.py` | Matplotlib-rendered view of the sharpened combined image, likewise saved with a `.TIF` filename. |
| `<base>_combined_processed_1d.png` | `RawImageProcessing.py` | PNG plot of width-wise population-density profiles derived from the unsharpened combined image. One line is plotted for each RGB channel. |
| `<base>_combined_processed_1d_sharp.png` | `RawImageProcessing.py` | Equivalent population-density plot derived from the sharpened combined image. |

## Important boundary

The mask and fluorescence stacks are source-data inputs, not outputs of this
repository's historical scripts. Files such as stitched bright-field images
without the `_mask`/`_MASK` suffix, other channels (for example `w1SD BF`),
and miscellaneous TIFFs present in a download are not read by this script's
main processing loops.

### Replicate-1 series-2 exception

The replicate-1 inventory contains 66 `_2`-series filenames: 33 under
`Chitin/11.19.21_10` and 33 under `NAG/11.20.21_10`. Each series comprises an
`.nd` file plus eight `w1SD_BF`, eight `w2SD_DAPI`, eight `w3SD_GFP`, and
eight `w4SD_RFP` TIFF files. It has no matching
`<acquisition>_2_w1SD BF_stitched_MASK.tif` file.

Neither implementation processes those series. The historical script loops
over their directories but constructs only `_1` mask and channel paths; with
this inventory, it would fail at the first such directory when its expected
`_1` mask is absent. The non-interactive implementation first discovers only
`*_1_w1SD BF_stitched_mask.tif` masks and then constructs only `_1` tile
paths, so it skips the two series-2 directories. The metadata currently lists
both acquisitions, making the missing-mask/series-2 treatment an open
workflow question rather than evidence that they were intentionally included
in either raw-processing run.

The current non-interactive implementation in
[`experiment_analysis.py`](../experiment_analysis.py) accepts either mask
capitalization and retains the four per-channel products plus the combined
TIFFs and pickle. It creates `<base>_preview.png` in place of the historical
`*_small.TIF` and `*_1d*.png` display products.
